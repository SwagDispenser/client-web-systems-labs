# Система управління бібліотекою

Клієнтський TypeScript-застосунок для ведення каталогу книг, читацьких профілів,
позичання та повернення книг. Інтерфейс повністю створюється через DOM API — у
`index.html` немає декларативної розмітки застосунку, окрім кореневого
`<div id="app"></div>`.

## Можливості

- додавання і видалення книг та користувачів;
- валідація всіх полів із повідомленнями біля відповідних елементів форми;
- пошук книг за назвою або автором без урахування регістру;
- позичання книги за числовим ID користувача;
- повернення книг і синхронне оновлення стану книги та користувача;
- обмеження до трьох одночасно позичених книг;
- власні модальні вікна і toast-сповіщення без використання `alert`;
- пагінація книг і користувачів по п'ять записів;
- автоматичне збереження і відновлення стану через `LocalStorage`;
- адаптивний інтерфейс на Bootstrap із власними SCSS-стилями.

## Технології

- TypeScript у строгому режимі;
- webpack, webpack-dev-server і ts-loader;
- Bootstrap 5, підключений як npm-залежність через webpack;
- Sass;
- Mocha та Chai;
- ESLint і Prettier;
- Husky для автоматичного запуску лінтера й тестів перед комітом.

## Архітектура

```text
src/
├── models/                 # моделі Book і User та їхні інтерфейси
├── services/               # бізнес-логіка, сховище, пагінація і сповіщення
├── styles/                 # власні SCSS-стилі
├── ui/
│   ├── components/         # форми, списки, модальні вікна, пагінація
│   └── render.ts           # компонування і оновлення DOM
├── utils/                  # Validation namespace та генератор ID
└── index.ts                # створення залежностей і запуск застосунку

tests/                      # модульні тести Mocha
```

Шари `models`, `services` і `utils` не працюють із DOM. Вся DOM-логіка ізольована
в `ui`. Generic-клас `Library<T>` керує типізованими колекціями, а generic-класи
`Storage<T>` і `Paginator<T>` забезпечують типобезпечне збереження та пагінацію.
Простір імен `Validation` об'єднує функції перевірки форм.

## Запуск

Потрібна актуальна LTS-версія Node.js.

```bash
npm install
npm start
```

Dev-сервер відкриває застосунок за адресою
[http://localhost:9000](http://localhost:9000).

## Команди

```bash
npm start          # webpack dev-server із HMR
npm run build      # production-збірка в dist/
npm run typecheck  # перевірка TypeScript без генерації файлів
npm run lint       # ESLint
npm run format     # форматування Prettier
npm test           # модульні тести Mocha
npm run deploy     # публікація dist/ у lab-02 гілки gh-pages
```

Перед кожним комітом Husky автоматично виконує `npm run lint` і `npm test`.
Коміт блокується, якщо будь-яка перевірка завершується помилкою.

## Основні правила предметної області

1. ID користувача містить лише цифри.
2. Рік видання — чотиризначне число, не більше поточного року.
3. Одну книгу не можна одночасно видати двом користувачам.
4. Один користувач може позичити не більше трьох книг.
5. Видалення позиченої книги прибирає її з профілю користувача.
6. Видалення користувача автоматично повертає всі його книги.

## Тестування

Тести перевіряють:

- додавання, видалення і пошук у `Library<T>`;
- обов'язкові поля, числовий ID, email і рік видання у `Validation`;
- зміну стану моделей `Book` і `User`;
- позичання, повернення, ліміт у три книги та цілісність зв'язків;
- серіалізацію в `Storage<T>`;
- пагінацію та сервіс сповіщень.

Повний локальний контроль перед передачею роботи:

```bash
npm run format:check
npm run typecheck
npm run lint
npm test
npm run build
```
